# HiveOS custom miner — keryx-miner-supr

HiveOS rigs run an **older glibc** (Ubuntu 20.04 = glibc 2.31) than the dev rig
(Ubuntu 24.04 = glibc 2.39). A binary built natively on the dev rig needs up to
`GLIBC_2.39` and fails on HiveOS with `version 'GLIBC_2.3x' not found`. This
directory builds a glibc-2.31 binary in a container and wraps it in the HiveOS
custom-miner format.

## Build the release archives

The maintained entry point performs a network-isolated modern NVIDIA build and
then creates every supported distribution package:

```bash
hiveos/build-release.sh
# -> hiveos/dist-modern/keryx-miner-supr-modern-<ver>.tar.gz
# -> hiveos/dist-modern/keryx-miner-supr-smos-modern-<ver>.tar.gz
# -> hiveos/dist-modern/keryx-miner-supr-modern-mmpos_<ver>.tar.gz
# -> hiveos/dist-modern/keryx-miner-supr-modern-<ver>-linux-x86_64.tar.gz
# -> hiveos/dist-modern/SHA256SUMS-modern.txt
```

It requires a clean llama.cpp `b10015` checkout and portable CMake >= 3.18 as
documented at the top of `build-offline.sh`. Both AVX2 and baseline-ISA CUDA
llama engines are built inside the same `--network none` container; packaging
fails if either engine, the CUDA worker, or any CUDA runtime library is missing.

- **linux-x86_64** = NVIDIA dynamic host plus `libkeryxcuda.so` for general Linux.
- **HiveOS/SMOS/mmpOS** = static CUDA worker host plus the relevant integration scripts.
- Every flavor includes both GPU inference engines and its CUDA runtime closure.

The old `hiveos/package.sh` path is retired because it omitted the mandatory
inference engines. `build-glibc.sh` remains useful as a compile-only diagnostic;
use the line workflow for anything distributed to rigs.

A miner process has one compile-time Proof-of-Model backend. On mixed AMD/NVIDIA
rigs, run the AMD `pom-opencl` package and NVIDIA `pom-cuda` package as separate,
device-scoped processes; combining both worker plugins beside one host is unsafe
post-fork. The retired `package-universal.sh` now fails closed instead of producing
that invalid layout.

`build-glibc.sh` prints the max `GLIBC_*` symbol of each artifact — it must be
`<= 2.31`. The legacy CUDA worker kernels (`keryx-cuda-sm120.ptx` etc.) are
pre-built and embedded, so the container does **not** regenerate them: sm_61–sm_90
use CUDA 12.2 / PTX 8.2, while sm_100/sm_120 use CUDA 12.8 / PTX 8.7. The modern
PoM walk separately embeds a CUDA 13.3 fatbin. `cust` links the CUDA *driver* API
(`libcuda.so.1`), which the installed NVIDIA driver provides on the rig.

> **Driver note:** the dedicated `sm_120` image is PTX ISA 8.7, generated by CUDA
> 12.8. RTX 50-series cards require a compatible 570-series-or-newer driver. If a
> newer virtual target cannot load, the worker attempts its older sm_86 PTX 8.2
> fallback.

## Package layout

The CUDA mining worker is linked into the HiveOS binary (`--features static-cuda`),
but OPoI inference still requires the bundled llama engines and CUDA runtime
closure. The rig's driver supplies `libcuda.so.1`.

```
keryx-miner-supr/
├── h-manifest.conf      # name / version / log + config paths
├── h-config.sh          # flight sheet -> CLI args
├── h-run.sh             # launches the miner (foreground)
├── h-stats.sh           # hashrate/shares from log + temps/fans from agent
├── keryx-miner-supr     # static CUDA-worker binary (glibc <= 2.31)
├── libkeryx-llama.so    # normal CUDA inference engine
├── libkeryx-llama-noavx.so # baseline host-ISA CUDA inference engine
└── lib/                 # cudart, cuBLAS/cuBLASLt, cuRAND
```

## Install on a rig (Flight Sheet)

1. Host the matching `keryx-miner-supr-<line>-<version>.tar.gz` at a URL the rig can reach
   (e.g. a GitHub release asset).
2. HiveOS → **Flight Sheet** → Miner = **Custom**:
   - **Installation URL**: the tarball URL
   - **Miner name**: auto-filled from the archive (`keryx-miner-supr-modern`, `-legacy`, or `-amd`)
   - **Hash algorithm**: `keryxhash`
   - **Wallet and worker template**: `keryx:<addr>.%WORKER_NAME%`
   - **Pool URL**: `stratum+tcp://krx.suprnova.cc:4401` (the scheme is required)
   - **Pass**: as needed (keryx pools usually ignore)
   - **Extra config arguments**: optional. **Blank = per-card AUTO** (each GPU loads the
     heaviest model its VRAM can hold = max reward). Pass a tier flag like `--very-high`
     to pin all cards to one tier, or `--force-model <csv>` to set a model per GPU. See
     [FLIGHT_SHEET.md](FLIGHT_SHEET.md#4-extra-config-arguments--reference) for all model/tier options.

Stats (hashrate, accepted/rejected, per-GPU) report back to the HiveOS dashboard
via `h-stats.sh`.

# H16 per-card kernel development — 2026-11-08

These measurements compare a local development candidate with the frozen
v0.16.2 build from source `faf7fff34b6d1751eb612020b098c04356bb8af2`.
They use the complete miner, H16 jobs and tier 0 (Qwen3.5-9B), with mining and
inference sharing one GPU. They are not a published release benchmark.

## Method

The baseline and candidate ran on the same physical card with the same driver,
model, power limit and clock policy. Most rows use A/B/B/A order, 120 seconds of
measurement per arm after warm-up; the RTX 3070/5080 use 90 seconds per arm.
The 600 W RTX 5090 result is a single A/B control. Reported power and clocks are
GPU telemetry, not wall power. CPU percentages refer to one logical CPU core.
The two rig GPUs in the 3070/5080 test ran concurrently in both arms; all other
benchmark rows used one test GPU at a time. Original card settings were restored.
The share difficulty is fixed within each comparison: 0.001 for the 5090,
0.0004 for the 3070/5080, and 0.0002 for AMD. CPU work includes proof construction,
so compare CPU percentages within a row rather than across different difficulties.

A private loopback job source supplies fixed H16 headers at DAA 148,000,000.
The API rate measures completed hashing work; captured submissions are separately
checked against the unmodified node v1.6.7 consensus code and assigned target.
Loopback acknowledgements do not establish live pool acceptance. Different
model tiers and older H15/v4 results are not directly comparable.

## Changes

CUDA adds two optional layouts that stage integer matrix fragments before
reusing the tile buffer. This lowers shared memory from 3 KiB to 2 KiB per nonce.
Independent nonce trees share the Merkle finish work. All 168 established native
functions across 12 architectures retain identical machine instructions.
The existing layouts remain candidates in the per-card timing comparison.

AMD adds an exact cooperative INT8 matrix walk on supported wave32 hardware,
coalesced vector tile loads, and a variant that resolves a tile address once
and broadcasts it. Tiles spanning tensor boundaries retain the exact gather.
A separate integer-dot variant uses subgroup XOR reductions for the state fold;
on wave64 each 32-lane nonce stays independent. Fixed-wave devices do not request
an unsupported subgroup size.

The Vulkan engine also chooses between 1,024, 4,096 and 8,192 nonces per dispatch.
It measures the current card and resident model, keeps measured launches within
20 ms, and retains cancellation between sub-dispatches. The optional ABI-1 batch
query lets the frontend use that result; older sidecars retain the 1,024 default.
Linux and Windows shader recipes include all new variants and the Windows export
list includes the optional query.

## Correctness and build checks

The CUDA layouts passed 700 exact-target/one-below-target checks and 20 partial
batch checks on each tested SM86 and SM120 GPU, over five pad sizes. AMD checks
cover CPU-derived walk values, tensor boundaries, pad bytes, seed replacement,
partial batches, and allocations spanning the 1 GiB pad-shard boundary.
Captured complete mining proofs pass the unmodified node v1.6.7 verifier at the
assigned target; altered roots, the wrong fork-era pad and a target one below
the actual value are rejected. This check covered 400 proof samples from 40
completed benchmark arms. Full H16 inference, attention verification, custody
upload, restart/fetch/replay and mining-resume checks passed on the RTX 5090,
RX 7900 XTX, RX 7600 XT and healthy MI50.

The final Linux frontends passed 140 CUDA and 129 AMD host tests, plus a mixed-tier
proof regression. Loader/native-environment checks passed on Ubuntu 20.04, 22.04
and 24.04 with the normal OpenCL/OpenMP dependencies and no exposed GPU devices.
The final XTX wrapper includes an error-path lifetime fix after its timed runs;
all 14 shader binaries are identical, and its final mining run repeated
1.0999 MH/s. The final CUDA frontend likewise retains the measured kernel
instructions and passed another mining/proof check.

## Selection and limits

Every new kernel must first match the existing exact implementation on the live
model before entering a warmed, alternating-order timing comparison. New paths
need at least a 0.5% measured advantage to replace the established choice.
Selection belongs to the actual card/model owner, not a blanket architecture
switch. Restart after changing clocks or power policy so it measures that setup.
Existing kernels remain available on unsupported devices or failed cross-checks.

Diagnostic overrides:

- CUDA: `KERYX_POM_V5_INPLACE=0` excludes the new layouts.
- Vulkan: `KERYX_VK_V5_MODE=sp` retains the established kernel and fixed batch.
- Vulkan: `KERYX_VK_V5_SUB_DISPATCH` explicitly sets the bounded host sub-dispatch
  size (8–8,192); otherwise the engine's measured choice is used.

Physical qualification covers Ampere/Blackwell CUDA and the tested AMD devices.
Windows GPU execution, other physical architectures and higher model tiers were
not separately benchmarked in this investigation. No consensus rules, model
weights, inference engine arithmetic, drivers or firmware were changed.

# H15 CMP and RTX 3070 cache measurements — 2026-11-05

These local development measurements compare the previous solver candidate
`e3c185a` with the changes compiled from `48dd938`. They are not comparisons
against a public release. The experiment itself did not publish a release; its selected changes are
included in v0.16.0.

| GPU | Model tier | Power limit | Control MH/s | Selected MH/s | Gain | Steady CPU, one core |
|---|---:|---:|---:|---:|---:|---:|
| CMP 170HX | 3 | 200 W | 1.447369 | 1.521961 | +5.154% | 0.87% |
| RTX 3070 | 0 | 240 W | 1.279536 | 1.288523 | +0.702% | 2.92% |

Each comparison uses the same physical card, driver, model, fixed H15 header,
batch, power limit and memory settings. Different tiers make the two absolute
rates unsuitable for a direct comparison between cards. Every arm runs for
120 seconds after readiness; the first 40 seconds are excluded. CPU measures
the miner and any owned IPFS child, excluding the test harness; no IPFS child
was needed during these mining arms. Inference/startup CPU is outside that window.
The fixture uses a loopback endpoint and does not establish pool acceptance.

CMP used A/B/C/C/B/A: A is the preceding solver, B enables the exact fast solver
on SM80, and C also uses cached asynchronous tile loads. B gained 4.363% over A;
C gained another 0.757% over B. The paired repeats differed by 0.255%, 0.141%
and 0.224%, respectively. Selected average telemetry was 198.98 W, 1209 MHz SM,
1728 MHz memory and 75.31 C core. The interrupted first C arm was excluded and
replaced by a complete run.

RTX 3070 used A/B/B/A with the cache change embedded in the miner. The two
control repeats differed by 0.041%, and the selected repeats by 0.120%.
Selected averages were 239.51 W, 1700 MHz SM, 6801 MHz memory and 57.09 C core.
Both improvements were measured under a power limit with automatic graphics
clocks; they are not fixed-clock IPC measurements.

The final Linux binary is
`7684e694411928fe8b7a663186c50fb4f7035155f4210b56d633bf92b7daf485`.
CMP performance used the exact selected external CUDA image; RTX 3070 used
the preceding embedded build with identical SM86 instructions and host policy.
Instruction comparisons bind those measurements to the final binary. Final
CMP CPU/GPU exactness used the test executable with the selected CUDA image;
the RTX 5090 workflow check used the final miner binary.

## Selection and correctness

The change enables the exact fast solver on SM80 and uses L1-cached asynchronous
tile loads on SM80/SM86. Shared-memory carveout, L2-persistence settings and the
INT8 tensor path remain unchanged. Increasing L1 preference at the expense of
shared memory substantially reduced throughput in the tested synthetic fixture;
persistence variants produced no useful repeatable gain. An exact FP16 alternative
was slower on both tested cards and was excluded. No driver or unlock changes
were required, and no new CPU workers or polling loops were added.

Both physical architectures passed 700 individual exact-target/one-below and
20 batch-target checks against independent CPU results over five pad sizes.
Tests cover partial workgroups, off-lane winners and current/future H16 pad sizes.
The H16 activation gate was disabled in these development measurements;
v0.16.0 separately integrates the official activation gates. Established entry points and SM120's
fast kernel retain identical instructions. `KERYX_POM_V5_FAST=0` retains the
established fallback, and inference engines and libraries are unchanged.

The final binary passed the H15 answer, independent proof and attention checks,
tamper rejection, custody upload/readback, restart and mining resume on RTX 5090.
These fixtures are not live network acceptance or live H16 validation.

## CMP qualification limit

An initial CMP run at 250 W reached the 85 C guard and was excluded. The matched
mining runs completed at 200 W. During final H15 replay, telemetry later reported
273.35 W despite a 200 W setting, with core 67 C and memory 72 C. The unchanged
power guard stopped the attempt. The miner exited with signal 11 during forced
shutdown; no new Xid/AER was recorded. Answer generation, custody upload and
fetch after restart completed, but proof opening and mining resume did not.
Full CMP H15 workflow qualification therefore remains incomplete. No further
CMP load was attempted; the card was left idle with its original settings.

Windows, macOS, AMD and other GPU performance were not newly tested here.
Normal cross-platform qualification remains necessary before a release.
